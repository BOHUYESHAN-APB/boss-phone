## 1. 产品概述

### 1.1 一句话定位

把 FoloToy AI Passport 变成一部"领导的手机"：一个微型手机系统（桌面 + 电话簿 + 备忘录 + 设置），用户以领导视角，通过打电话的隐喻（电话簿、拨号、来电、语音指令）远程指挥电脑上的多个 AI 编程 Agent（Claude Code / Codex / OpenCode / Trae 等）在各自仓库中工作。

### 1.2 核心理念

1. **板子是哑终端**：只负责显示、三键、音频输入输出。所有智能（STT、意图理解、Agent 调度）都在 PC 端。这是 ESP32-C3 硬件约束（400KB SRAM、无 PSRAM）下的必然选择，也是产品可维护性的来源——Agent 逻辑更新不需要烧固件。
2. **一套协议，四种传输**：USB 有线、局域网 WiFi、BLE 伴侣、（未来）板载 LTE 共用同一套消息协议，差异全部下沉到传输层。兼容性是架构的自然结果，不是补丁。
3. **三端联动，而非单端切换**：设备、手机、电脑各自感知环境并协同决策链路路由。设备在局域网内时，手机零负担（不收任何推送）；插着 USB 时一切流量走有线，最稳且零电池消耗。
4. **手机系统体验**：不做单一功能的"工具屏"，而是完整的小型手机系统——状态栏、桌面、应用宫格、事件弹窗层。界面不单调，且天然可扩展新应用。
5. **领导体验优先**：一切交互隐喻为"打电话"。用户不需要理解"Agent / 会话 / 权限请求"这些术语，只需要认识"联系人"和"红黄绿灯"。

### 1.3 目标用户

- 同时用多个 AI CLI Agent 管理多个仓库的开发者（个人使用为主）。
- 希望离开电脑（挂脖在身、在屋里走动、出门在外）仍能：掌握 Agent 状态、批准权限请求、下达语音指令、收到异常报警的用户。

### 1.4 核心体验叙事（用户故事）

> 早上到工位，把挂脖的"手机"插上 Type-C——屏幕常亮，进入"工位模式"：顶部状态栏显示充电中·USB 链路，桌面红黄绿总览一眼看清三个仓库的状态。按两下进电话簿，拨给接线员："喂，让小张把测试跑一遍。"顺手在备忘录里录一条"下午提醒我看内存泄漏"。
> 中午拔线去食堂，板子自动切 WiFi；走出公司大门 WiFi 断开，蓝牙自动回连口袋里的手机，全程无感。
> 下午人在楼下便利店，口袋里的手机震了一下——repo-B 等你批权限，屏幕亮起来电界面。长按 OK 说一句"允许"，继续挑咖啡。
> 回到家插上线，备忘录自动同步到 PC，转写文字回填标题，其中"内存泄漏"那条可一键派发给 repo-A 的小张。

## 2. 用户场景与链路形态

| 场景 | 链路形态 | 说明 |
|---|---|---|
| S0 工位/家里（插线） | 板子 —USB→ PC 总机房 | 供电 + 传输二合一，零电池消耗，屏幕常亮，最稳 |
| S1 室内自由活动 | 板子 —WiFi→ PC 总机房 | 直连，零公网暴露，延迟最低 |
| S2 户外（手机在身边） | 板子 —BLE→ 手机 App —4G/5G→ 云中继 ⇄ PC 隧道 | 手表同款架构，手机与板子均低功耗 |
| S3 户外（手机不在身边） | 板子深睡；消息积压云端队列 | 回连后 sync 补收，来电不丢 |
| S4 大流量任务 | 板子 —手机热点→ 云中继 | 仅 OTA/日志导出时 App 临时开热点，用完即关 |
| S5 未来 LTE 板 | 板子 —4G→ 云中继 | 可脱离开手机独立成机，支持真人语音通话 |

**链路优先级（板端链路监管器自动决策）**：

```
USB 已插入且 PC 端网关在位     → USB 有线模式（供电+传输，屏幕常亮）
检测到已知 SSID（到家/办公室）  → WiFi 直连（同时断 BLE 省电）
已配对手机在 BLE 范围内        → BLE 伴侣模式
BLE 断开且无 WiFi              → 深睡，等推送唤醒或定时回连
大流量任务（OTA 等）            → USB 可用走 USB；否则请求 App 临时开热点
```

### 3.1 组件总览

```
┌─────────┐  USB / WiFi / BLE / (LTE)  ┌──────────────────┐        ┌──────────────┐
│ 📟 板子  │ ⇄────────────────────────⇄ │ 🖥️ PC 总机房      │ ⇄─────⇄ │ ☁️ 云中继     │
│ 微型手机 │                            │ · 网关/会话管理    │        │ (阶段 3 引入) │
│ 系统     │                            │  (WS + USB CDC)   │        └──────┬───────┘
└─────────┘                            │ · 接线员 Agent    │               │ 厂商推送
                                        │ · 调度中枢        │        ┌──────▼───────┐
┌─────────┐      BLE                    │ · 插件桥          │        │ 📱 手机 App   │
│ 📱 安卓  │ ⇄────────────────────────⇄ │                  │        │ (控制+数据面) │
│ 伴侣 App │  (口袋网关)                 └────────┬─────────┘        └──────────────┘
└─────────┘                                     │ 统一插件协议
                                      ┌─────────▼────────┐
                                      │ 🔌 CLI Agent 插件  │
                                      │ Claude Code/Codex │
                                      │ OpenCode/Trae     │
                                      └──────────────────┘
```

### 3.2 各组件职责

| 组件 | 职责 | 关键约束 |
|---|---|---|
| 板子固件 | 微型手机系统（状态栏/桌面/应用框架/事件弹窗层）、三键统一导航、音频采集/播放、传输层抽象（usb/ws/ble）、链路监管、消息去重、备忘录本地存储、亮度与息屏管理 | 400KB SRAM；TinyUSB + LVGL + 音频共存需严控内存 |
| PC 总机房 | WebSocket + USB CDC 双入口网关、设备会话管理、链路路由决策（直连/中继）、事件总线、离线队列、来电调度、备忘录转写（STT）与回填、遥测聚合（PC 资源采集、token 用量统计、commit/CI 状态查询） | 单机运行，无需公网 IP（出站隧道） |
| 接线员 Agent | 多模态大模型（音频直听或 STT），理解语音指令 → 路由到具体 Agent / 转达任务；接收备忘录派发 | PC 端调用云端 API，模型可替换 |
| 调度中枢 | Agent 注册表、状态聚合、权限请求队列、多设备消息扇出 | — |
| 插件桥 | 各 CLI 装统一插件：上报状态、转发权限请求、收回回答 | 每个 CLI 一份适配层，协议统一 |
| 云中继 | 公网撮合点：PC 与手机/板子均主动外连（出站隧道，免端口映射，可穿 CGNAT）；推送代理 | 阶段 3 引入；UPnP 端口映射仅作直连加速 |
| 安卓伴侣 App | 厂商推送保活、BLE 网关（数据面）、软终端 UI（没带板子时手机直接批权限）、临时热点控制 | 各厂商后台限制需引导白名单 |

### 3.3 协议兼容三原则（不可妥协）

1. **只增不改**：消息类型与字段只增不删不改语义；未知字段一律忽略。
2. **hello 版本协商**：每次连接握手交换 `proto` 版本，取双方共同版本。
3. **caps 能力降级**：设备/总机各自声明能力集，网关按对方能力裁剪功能。

老固件永远可用；未来 LTE 板在 hello 里多声明 `"lte"` 即插即用。

## 4. 多端联动链路系统（核心需求）

这是本产品的差异化设计：**链路路由不是板子单方面决定，而是多端协同感知、各司其职。**

### 4.1 板端状态机

```
   ┌────────────────────────────────────────────────┐
   │              USB 插入 + 网关在位                 │
   │              （最高优先级，随时抢占）              │
   ▼                                                │
┌───────────┐   WiFi 关联成功                        │
│DESK_USB   │ ──────────────────────────┐           │
│ CDC 会话  │                           ▼           │
│ 屏幕常亮  │                      ┌──────────┐      │
└───────────┘                      │LAN_ONLINE│      │ WiFi 断开
   ▲   拔线后回落到次优链路           │ WiFi+WS  │──────┐
   │                                │ BLE 关闭 │      ▼
   │                                └──────────┘  ┌───────────┐  BLE 回连超时(5min)
   │        WiFi 重新关联 / 插线 ────────▲──────────┤ BLE_ONLINE│ ──────────→ ┌────────────┐
   │                                    │          │ BLE 回连  │              │ DEEP_SLEEP │
   └────────────────────────────────────┘          └───────────┘ ←─定时唤醒── │ 等推送/定时 │
                                                                              └────────────┘
```

| 状态 | USB | WiFi | BLE | 屏幕 | 说明 |
|---|---|---|---|---|---|
| DESK_USB | 已连接，CDC 会话活跃 | 可选关闭 | **关闭** | 常亮（充电中） | 工位稳态：最稳、零消耗 |
| LAN_ONLINE | 断开 | 已连接，WS 会话活跃 | **关闭**（省电，手机零负担的前提） | 常规策略 | 室内活动稳态 |
| BLE_ONLINE | 断开 | 断开/扫描中 | 开启，回连已配对手机 | 常规策略 | 户外稳态 |
| DEEP_SLEEP | 断开 | 断开 | 低频广播或关闭 | 熄灭 | 手机不在身边；定时唤醒试回连 |

### 4.2 PC 端路由决策（总机房）

PC 通过各入口（USB CDC / WebSocket）心跳判断设备可达性：

```
USB CDC 会话活跃 → USB 路由（最高优先级，一切流量走有线）
心跳正常（WS 会话活跃）→ DIRECT 路由：消息直达板子，不向云中继/推送通道发任何东西（手机零负担）
心跳超时（设备离开局域网）→ RELAY 路由：消息上云中继 → 厂商推送 → 唤醒手机 App → BLE 送达板子
                     → 事件写入离线队列（seq 递增），防丢
设备重新可达（任一入口）  → 切回直连；设备端按 seq 去重（双链路瞬间并存时消息可能重复到达）
```

### 4.3 手机端行为

| 情形 | App 行为 | 手机负担 |
|---|---|---|
| 设备在 USB/WiFi | 收不到任何推送，BLE 不活跃 | **零** |
| 收到推送（设备离网） | 激活 → 连 BLE → 中转消息 → 显示通知 | 低（一次唤醒 + BLE 常连 mA 级） |
| 用户没带板子 | App 自己就是软终端，直接批权限/看状态 | 无 BLE，纯 App |

### 4.4 边界情况

| 情形 | 处理 |
|---|---|
| 插线瞬间 WiFi 会话还在 | 双链路并存窗口期，板端按 `seq` 去重；USB 稳定后关 WiFi 射频省电 |
| 刚到家：WiFi 已连但 BLE 未断 | 双链路并存窗口期，板端按 `seq` 去重；WiFi 稳定后主动关 BLE |
| 插着线但 PC 网关没开 | USB 仍供电充电；传输回落到 WiFi（链路监管器按"会话在位"而非"仅插线"决策） |
| 手机杀后台且厂商推送未达 | 云端队列兜底；板子下次任何链路上线即 sync 补收 |
| 局域网内 PC 重启 | 设备自动重连（指数退避）；重连期间事件积压队列，不丢 |
| WiFi 有信号但断网（外网故障） | 局域网内直连不受影响（总机房在 PC 本机）——直连路由的天然优势 |

## 5. 功能需求

优先级定义：P0 = MVP 必须；P1 = 完整体；P2 = 后续阶段。

| FR-21 | 离线队列与 sync | P1 | 每设备事件 seq 递增；重连后 `sync(since_seq)` 补收；板端按 seq 去重 |
| FR-22 | 云中继 | P2 | 出站隧道撮合（免端口映射、穿 CGNAT）；UPnP 仅作直连加速 |
| FR-23 | 厂商推送 | P2 | FCM/小米/华为/OPPO/vivo（可极光/个推聚合）。推送只唤醒 App，不承载业务数据 |
| FR-24 | OTA | P2 | 优先 USB/WiFi；BLE 链路禁止 OTA |
| FR-39 | 文件传输 | P1 | 统一 `file` 消息（分块、断点续传语义）：备忘录上传、头像下发、OTA 镜像共用 |

### 5.9 总览驾驶舱（遥测面板）

总览应用为**面板化驾驶舱**：▲▼ 在面板间循环切换（Agent 状态 / Token 消耗 / PC 资源 / 提交与 CI），所有数据由 PC 端推送，板子只显示不计算。遥测消息走既有信封与 seq 机制，断线时计入离线队列，BLE 链路下自动降频。

| ID | 功能 | 优先级 | 描述 |
|---|---|---|---|
| FR-45 | 面板 1 · 状态与系统 | P0 | 各 Agent 红黄绿灯一行一条（名称 + 简要状态），底部：电量、当前链路、存储占用 |
| FR-46 | 面板 2 · Token 消耗 | P1 | 今日总量（tokens + 估算费用）、各 Agent 分项、本月累计与预算进度条。数据源：插件上报会话 usage（Claude Code hooks usage / 各 CLI JSON 输出），总机房按日/月聚合，变更时增量推送 |
| FR-47 | 面板 3 · PC 资源 | P1 | PC 端 CPU %、内存占用、运行中 Agent 会话数、总机房 uptime。`telemetry` 消息周期推送（USB/WiFi 30s，BLE 2min）；PC 过载（CPU 持续 >90% 或内存告急）时主动告警一次 |
| FR-48 | 面板 4 · 提交与 CI | P1 | 各仓库最近一次提交（短 sha + 消息摘要 + 是否已推送）与 CI 状态（通过/失败/运行中）。commit 由插件上报；CI 状态由 PC 端查询（GitHub API / gh）。**CI 失败 = 仓库红灯**，走既有报警链路（响铃 + 事件层弹窗） |
| FR-49 | 卡死检测 | P2 | 总机房综合遥测判断 Agent 卡死（CPU 无变化 + 长时间无输出心跳）→ 标红并来电提醒"疑似卡死，是否重启会话" |

## 6. 交互规范

### 6.1 统一导航语义（全局唯一事实表）

三键撑起整个手机系统，核心是"**长按 ▲ = 全局后退**"的后退语义：

| 按键 | 短按 | 长按 |
|---|---|---|
| ▲ 上键 | 上移一项 | **后退**：上一级页面；问答=上一题（在 Q1 再长按=退出问答）；通话中=挂断 |
| ▼ 下键 | 下移一项 | 问答=下一题（多选切题）；列表=快速到底 |
| OK 键 | 进入/确认/接听/播放暂停 | 语音输入（可输入场景）；桌面=快捷拨号接线员；来电=拒接；备忘录=开始/停止录音 |

### 6.2 屏幕清单

| 屏幕 | 内容 |
|---|---|
| 桌面 | 状态栏（时钟·电池·链路）+ 红黄绿总览卡片 + 应用宫格（电话簿/备忘录/设置/总览） |
| 电话簿 | 联系人列表（头像 \| 名称 \| 状态灯），见 FR-01 |
| 联系人详情 | Agent 名、仓库、CLI 类型、状态摘要、当前任务、最近提交（sha+消息）、CI 状态、今日 token 用量 |
| 通话中 | 对方头像 + "通话中"，录音时显示波形/计时 |
| 权限请求 | 题号（Q n/m）、题目、选项列表（可勾选态）、单选/多选标识 |
| 来电（事件层） | 全屏：来电方头像+名称、阻塞原因摘要、接听/拒接提示；压在任意应用之上 |
| 备忘录列表 | 各条备忘：日期、时长、已转写标题（或"未转写"）、派发状态 |
| 备忘录音中 | 波形 + 计时 + 停止提示 |
| 备忘详情 | 转写全文（可滚动）、播放、派发、删除 |
| 总览驾驶舱 | 面板化（▲▼ 切换）：① Agent 红黄绿 + 电量/链路/存储 ② Token 消耗（今日/分项/月度预算）③ PC 资源（CPU/内存/会话数）④ 提交与 CI（sha + 消息 + CI 状态） |
| 设置各页 | 显示/链路/声音/联系人/关于，见 5.8 |
| 链路详情 | 当前链路、信号、上次同步 seq |

### 6.3 多选题的切题规则（用户明确要求）

- 单选：OK 选中某项 → **自动跳下一题**。
- 多选：OK 勾选/取消勾选，**不自动跳题**；长按 ▲▼ 显式切上一题/下一题。
- 存在"需用户输入"字段：该题显示"长按 OK 语音输入"提示。

## 7. 通讯协议

### 7.1 消息信封（所有链路一致）

```json
{
  "type": "state | ask | answer | voice | ring | sync | file | ...",
  "from": "agent:repo-b | hub | operator | device",
  "to":   "device | operator | agent:repo-c",
  "seq":  12345,
  "payload": {}
}
```

### 7.2 消息字典

| type | 方向 | payload 关键字段 | 说明 |
|---|---|---|---|
| hello | 设备→总机 | proto, device, fw, caps[] | 握手 + 版本/能力协商（USB/WS/BLE 各链路同构） |
| hello_ack | 总机→设备 | proto, caps[] | 确认协商结果 |
| presence | 插件→总机 | agent_id, online | Agent 上下线 → 电话簿增删 |
| state | 插件→总机→设备 | agent_id, state, summary | state ∈ running / waiting_input / blocked |
| ask | 插件→总机→设备 | ask_id, agent_id, questions[{kind, options[], multi, needs_input}] | 权限请求/提问，支持多题 |
| answer | 设备→总机→插件 | ask_id, answers[{selections[] \| text}] | 回答回传 |
| voice | 设备→接线员 | opus 帧 | 语音片段（压缩） |
| voice_ack | 接线员→设备 | transcript, intent, route | 转写与解析结果 |
| ring | 总机→设备 | agent_id, reason, summary | 来电（含红灯报警触发） |
| ring_ack | 设备→总机 | accept / reject | 接听/拒接 |
| audio | 双向 | opus 帧 | 通话中音频 |
| hangup | 双向 | — | 挂断 |
| file | 双向 | file_id, kind(memo/avatar/ota), chunk, offset, total | 分块文件传输：备忘上传、头像下发、OTA 共用 |
| file_ack | 双向 | file_id, offset | 分块确认/续传 |
| telemetry | 总机→设备 | cpu, mem, agents_active, uptime | PC 资源周期遥测（USB/WiFi 30s，BLE 降频 2min；离线时段不补发，只发最新值） |
| usage | 总机→设备 | today{tokens, cost}, per_agent[], month{tokens, cost, budget} | Token 消耗聚合，变更时增量推送 |
| commit | 插件→总机→设备 | agent_id, sha, branch, message, pushed | 最近提交（联系人详情与总览面板 4 显示） |
| ci | 总机→设备 | agent_id, status(pass/fail/running), summary | CI 状态查询结果；fail 转入红灯报警链路 |
| memo_result | 总机→设备 | memo_id, title, text | 备忘录转写回填 |
| memo_dispatch | 设备→总机 | memo_id, target | 备忘派发给接线员/某 Agent |
| sync | 设备→总机 | since_seq | 断线补收请求 |
| sync_data | 总机→设备 | events[] | 补收的事件批次 |

### 7.3 各链路传输实现

| 链路 | 载体 | 分帧 | 说明 |
|---|---|---|---|
| USB | TinyUSB CDC1（双 CDC：CDC0 调试台） | 直接 TLV/JSON 行帧 | 无 MTU 压力，全速 12Mbps；插线即最高优先级 |
| WiFi | WebSocket（局域网直连 PC） | WS 帧 | 带宽充裕 |
| BLE | 自定义 GATT（NUS 风格 RX/TX 特征值） | MTU 协商 247B + 分帧重组 + 轻量重传 | 连接参数：交互态 15-30ms，空闲态 100-500ms |
| LTE（未来） | 模块 TCP/UDP | 同 USB 分帧 | 新板 transport_lte 实现 |

### 7.4 音频规格

| 链路 | 编码 | 码率 | 说明 |
|---|---|---|---|
| USB / WiFi | Opus 16kbps（或 PCM） | ≤ 256kbps | 带宽充裕 |
| BLE | Opus 16kbps（备选 codec2 2.4kbps） | ≤ 32kbps | 对讲模式，延迟 1-2s 可接受 |
| 采样 | 16kHz 单声道 | — | 板端 ES8311 全双工采集（备忘录同规格） |

## 8. 非功能需求

### 8.1 电源与显示（官方基准：全亮 3-4h，低亮/息屏 8h）

| 模式 | 屏幕策略 | 电池消耗 |
|---|---|---|
| DESK_USB | 常亮（充电中） | **零消耗**（边充边用） |
| LAN_ONLINE | 自动降亮 → 超时息屏 | 中等（目标支撑工作日内碎片使用） |
| BLE_ONLINE | 激进降亮 → 快速息屏（事件即亮） | 低（目标日均 < 10mA） |
| DEEP_SLEEP | 熄灭 | μA 级 |

设计目标：插线工位 + 户外 BLE + 偶发充电的组合，满足 8 小时工作制整天使用。

### 8.2 其他

| 维度 | 指标 |
|---|---|
| RAM 预算 | TinyUSB + WiFi + BLE + LVGL + 音频缓冲共存需实测基线；互斥状态机保证不同时全开；LVGL 缓冲维持现状不加大（无 PSRAM，总量 400KB） |
| 状态延迟 | 状态变更 → 屏幕更新：USB/局域网 < 1s；BLE 链路 < 3s |
| 语音链路延迟 | 长按 OK 说完 → 接线员确认收到：< 3s（有线/局域网）/ < 5s（BLE+蜂窝） |
| 可靠性 | 消息不丢（seq 队列 + sync 补收）；不重（板端 seq 去重） |
| 兼容性 | 只增不改 + hello 协商 + caps 降级；老固件永不淘汰 |
| 隐私 | 局域网/USB 模式零公网暴露；云中继仅阶段 3+，且只转发信封（摘要 PC 端生成，可配置脱敏） |
| 安全 | BLE 配对绑定；WS/TLS；USB CDC 需简单配对码（防工位邻居插线冒充）；插件桥本机回环或局域网鉴权 |

| M4 LTE 板 | transport_lte、真人联系人（type:human）、语音直拨 | 新板插 SIM 即用，老板子不受影响 |

## 10. 风险与开放问题

| # | 风险/问题 | 等级 | 应对 |
|---|---|---|---|
| R1 | ESP32-C3 RAM：TinyUSB + WiFi + BLE + LVGL + 音频共存可能超预算 | 高 | M1 即建内存实测基线；状态机保证互斥（USB 时关 WiFi/BLE 射频）；必要时缩 LVGL 对象池 |

| Q2 | 头像资产：各公司 logo 版权与自定义头像上传方式？ | — | 默认首字母色块头像规避版权，logo 用户自行放入 |

| Q5 | 备忘录转写的 STT 与接线员是否共用同一模型/供应商？ | — | M2 前定，倾向共用降成本 |
